# Kenko v1.9.0 全链路轻量抛光设计

- **分支**: `feat/v1.9.0` 基于 `main`
- **日期**: 2026-09-01
- **范围**: App 使用、训练记录、显示、查询、动作记录、页面显示 6 流程各 1-2 点抛光
- **约束**: 离线单 APK 无后端；Material 3 Expressive + Zinc/#5E6AD2 参数化，不换设计语言；DB 微调需告知，默认不动；不大改 UI 样式；不做最近使用/收藏置顶

## 1. 背景与目标
Kenko 在 v1.8.0 完成 Linear 风格重塑（Zinc 中性 + 单主色 #5E6AD2、hairline 边框、6-14dp 圆角），v1.8.1 修复可读性与边框可见性。v1.9.0 以 NzHelper 的“部位→肌肉二级筛选”与 Linear 的“留白克制、字阶统一”为参照，对 6 流程做等权轻量抛光，达成：加一组 ≤3 次点击、动作库从入口到输入 ≤2 步、全站卡片字阶与空状态一致、无 DB migration。

## 2. 架构与隔离
- **分支与主题**: 全量改动复用 `Theme.kt` / `Border.kt` (`KenkoBorder`/`KenkoBorderStrong`) / `Typography`，不新增依赖。
- **单元划分**: 3 个可独立预览测试的单元：`AddSet` 手势容器、`Exercises/SelectExercise` 二级筛选、`Card` 字阶组件。单元通过 `MaterialTheme` 与现有 `ViewModel` 接口通信，不 penetrates `Repo/Dao`。
- **数据流**: 二级筛选数据源复用 `TagRepo.groupByParent`（`TagSelector` 已有），筛选状态为 UI 层 `rememberSaveable`，不落库。训练记录数值仍走 `AddSetViewModel` 的 `TextFieldState` + `InputTransformation`。
- **错误处理**: 筛选无结果 → `EmptyState` + “创建「关键词」”按钮；数值越界复用现有 `boundReached` 震动。

## 3. 训练记录流程（AddSet）
- **交互**: 保留三行 `SwipeableTextField` 视觉，行为以拖拽为主。`DraggableTextField` 横拖步进 `±1` 已支持，新增 `±1/±5` 按钮长按连发（400ms→80ms），减少反复点 `+/-10/20`。`Bodyweight` 行内切换不跳层。
- **视觉对齐（用户补充）**: 三行容器统一 `Modifier.fillMaxWidth().requiredHeight(44.dp)`，`Row` 用 `SpaceBetween` + 等宽按钮 + `DraggableTextField` 居中 `weight`，`Bodyweight` 态复用同宽占位，保证次数/组数/重量 Tab 长度一致、按钮纵向对齐。
- **焦点链**: `KeyboardOptions(imeAction=Next)` 次数→组数→重量串联已存在，仅确保不断链。
- **不做**: 不存历史重量、不引收藏。

## 4. 动作记录/动作库流程（浏览/搜索/创建）
- **导航压缩**: `Exercises → SelectExercise → AddSetSheet` 3 跳 → 2 跳。`Exercises` 与 `SelectExercise` 顶部复用 `TrainingDayBar` 的 `horizontalScroll` + `FilterChip`。
  - 一级：`All/胸/背/腿` 等部位 Chip（`BodyPartMuscleFilter`）。
  - 二级：选中部位后横滑展示该部位下肌肉 Chip，数据源 `Tag.groupByParent`，未选中时隐藏。
  - 选中态 `KenkoBorderStrong` + `primary 0.12` 底色，未选中 `KenkoBorder`。
- **创建闭环**: 搜索空列表主操作提供“创建「关键词」”按钮（复用 `label_create_exercise_name`），点击进入 `AddEditExercise` 后自动选中并回填 `SelectExercise` 的 `onDone`，`ExerciseItem` 点击即选中不二次确认。

## 5. 显示流程（卡片与字阶）
- **字阶统一**: 标题 `titleSmall`、数值/名称 `titleMedium + numbers()`、辅助描述 `labelSmall onSurfaceVariant`。统一 `StickyHeader/PlanItem/SessionCard/SetItem/DeletableSetItem` 的散落 `bodySmall 0.6-0.7f` 混用。
- **空状态**: `EmptyState` 已在 `PlanEdit/Exercises/Sessions` 复用，补充 `Sessions` 筛选无结果与 `WeightHistory` 的空文案，图标 `onSurfaceVariant 0.4f` 保持装饰性。
- **卡片容器**: 三行 `SwipeableTextField` 等长对齐已在 §3 描述；`PlanInfoCard/SessionCard` 等 `Surface` 保持 `outlineVariant` hairline，不新增阴影。

## 6. 查询流程
- **Sessions**: 保留 `ExposedDropdown`（计划/日期）+ `TrainingHeatmap`，仅优化联动：选“计划”后“训练日”下拉重置并即时过滤 `filteredSessions`，无结果统一 `EmptyState`。不新增常驻筛选条。
- **Exercises 搜索**: 复用 `ExercisesViewModel.searchQuery` 即时过滤，清除 `Close` 保留。不新增全文搜索，不改 `Heatmap` 交互。

## 7. App 使用与页面显示
- **入口**: `Home` 的“开始/继续训练”与 `PlanInfoCard` 逻辑不变，仅把“今日无计划”时的“切换训练日”文案与 `TrainingDayBar` Filter 样式对齐。
- **页面**: `TopAppBar/Scaffold` 保持 `surface`；`KenkoBottomBar` 的 `outlineVariant` hairline 已在 v1.8.1 加强（1.47）；`HorizontalDivider` 统一 `KenkoBorderWidth`；`FAB` 居中不动效。

## 9. 测试
- 预览：`PreviewLightDark` 在 `PlanItem/SetItem/AddSet` 已存在，新增筛选状态预览。
- 单元：`ExercisesViewModel` 搜索过滤、`AddSetViewModel` 边界 `boundReached`。
- 集成：`RoomDatabaseTesting` 的 `earliestSessionDate` 用例复用；`./gradlew assembleDebug` 必过。

## 10. 非目标
- 云同步、社交、图表动效大改、最近使用/收藏置顶、大规模 UI 风格重做、DB migration（本版不涉及，涉及则另行告知）。

## 11. 成功标准
- `AddSet` 加一组 ≤3 次点击（含选动作）；动作库入口到输入 ≤2 步；全站卡片字阶与空状态一致性通过视觉走查；无新增 migration 且 `assembleDebug` 通过。
